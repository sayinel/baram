# 레퍼런스 테마 (초안)

**성격:** 한글 본문 조판 우선 · 에디터 우선 (스펙 0055 §371.3).

**이 디렉터리는 아직 설치 가능한 패키지가 아니다.**

| 없는 것 | 누가 채우는가 |
|---|---|
| `light/tokens.json` · `dark/tokens.json` | 0095 (§367 색 시드·파생) |
| 정직한 `engines.baram` — 지금 값은 자리표시자다 | 0097 (§371 출고) |
| 번들 · 설치 · 출고 경로 | 0097 (§371) |
| 다이얼 값의 export | 0097 (§371.2) |

**`engines.baram` 이 `">=0.0.0"` 인 이유:** `theme-package-export.ts` 의
`MIN_BARAM_FOR_TOKENS_PACKAGE` 는 "이 패키지 포맷을 처음 설치할 수 있는 릴리스" 를
적는 자리이고, 그 상수가 릴리스 전에 같은 처지였을 때 `">=0.0.0"` 을 자리표시자로
썼다(주석: "그 릴리스가 실제로 나가는 날 그 버전 번호로 바꿀 것"). 이 레퍼런스는
**다이얼**을 싣는데, 다이얼을 읽는 첫 릴리스는 아직 번호가 없다 — 그것을 만드는
계획이 바로 지금 이 계획이기 때문이다. `MIN_BARAM_FOR_TOKENS_PACKAGE` 에서 값만
전사해 `">=0.7.4"` 를 적으면 "토큰 패키지 설치" 라는 무관한 사실을 빌려 오는 것이라
오히려 틀린 주장이 된다. 그래서 선례를 값이 아니라 **방식**으로 따라 `">=0.0.0"`
을 쓴다. 정직한 값은 0097(§371, 이 테마를 실제로 출고하는 계획)이 그날의 릴리스
버전으로 정한다.

**`modes` 가 가리키는 토큰 파일도 아직 없다.** `validateThemeManifest` 는 경로
문자열만 보고 디스크를 확인하지 않으므로 매니페스트 검증은 통과한다 — 그것이
이 초안이 "검증을 통과한다" 는 것과 "설치 가능하다" 는 것이 다른 이유다. 두 파일은
0095 가 채운다.

**있는 것:** 매니페스트와 다이얼 값. `src/themes/__tests__/reference-theme.test.ts`
가 그것을 실제 관문에 통과시키고, **레퍼런스가 행사하지 않는 다이얼을 명시적으로
열거하도록 강제한다.** 다이얼을 새로 더하면 그 테스트가 빨개지는 것이 설계다.
