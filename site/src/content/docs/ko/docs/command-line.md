편집기를 여는 바로 그 프로그램 `baram`은 터미널에서 볼트에 대한 질문에도 답합니다. 스크립트와 AI 에이전트를 위한 기능입니다. 앱을 열지 않고도 노트를 검색하고, 태스크를 나열하고, 링크를 따라갈 수 있습니다.

모든 명령은 **읽기만** 합니다. 볼트의 파일을 바꾸는 명령은 없습니다.

## 실행하기

이 명령은 앱의 실행 파일 그 자체입니다. 따로 설치할 것이 없습니다.

| 플랫폼         | 실행 방법                                                                 |
| -------------- | ------------------------------------------------------------------------- |
| macOS          | `/Applications/Baram.app/Contents/MacOS/baram`                            |
| Linux (`.deb`) | `baram` — 패키지가 `PATH`에 넣어 줍니다                                   |
| Windows        | 아직 확인되지 않았습니다. 명령은 들어 있지만, 출력이 터미널에 나오는지 확인한 사람이 없습니다. |

macOS에서는 셸 함수를 만들어 두면 전체 경로를 치지 않아도 됩니다. `~/.zshrc`에 넣습니다.

```sh
baram() { /Applications/Baram.app/Contents/MacOS/baram "$@"; }
```

심볼릭 링크 대신 함수나 alias를 쓰십시오. 앱이 링크를 통해 시작되면 업데이트 뒤에 스스로 다시 시작하지 못합니다.

인자 없이 실행하면 `baram`은 평소처럼 앱을 엽니다. `baram --help`가 명령 목록을 보여 줍니다.

## 볼트 고르기

명령 하나는 볼트 하나를 읽습니다. 다음 순서로 찾습니다.

1. `--vault <경로>` — 폴더입니다. 값에 `/`가 있거나 `.` 또는 `~`로 시작하면 경로로 읽습니다. 앱에 등록된 폴더가 아니어도 됩니다.
2. `--vault <이름>` — 앱이 그 볼트에 보여 주는 이름이나 별칭입니다. 대소문자는 가리지 않습니다.
3. `--vault`가 없으면, 현재 디렉터리를 포함하는 등록된 볼트입니다.

어느 것으로도 볼트가 정해지지 않으면 명령은 `VAULT_NOT_FOUND`로 멈추고, 같은 이름에 등록된 볼트가 둘이면 `VAULT_AMBIGUOUS`로 멈춥니다. 이때 뜻했을 만한 볼트를 함께 나열합니다. 앱에서 마지막으로 열려 있던 볼트로 대신하지 않습니다. 다른 곳에서 실행했을 때 엉뚱한 노트를 말없이 읽게 되기 때문입니다. 등록된 볼트는 `baram vaults`로 볼 수 있습니다.

등록된 폴더가 겹쳐 있으면 볼트가 일반 폴더보다 먼저이고, 볼트가 둘이면 바깥 것이 먼저입니다. 안쪽 볼트를 읽으려면 `--vault`를 주십시오.

## 명령

| 명령 | 출력하는 것 |
| --- | --- |
| `vaults` | 앱에 등록된 볼트와 폴더. `*`는 이 실행이 읽을 볼트입니다. |
| `files [--folder <경로>]` | 볼트의 마크다운 파일. |
| `read <경로>` | 파일 하나를 디스크에 있는 그대로. |
| `search <질의> [--regex] [--case-sensitive] [--word] [--folder <경로>] [--limit N]` | `.md` 파일에서 일치하는 곳마다 한 항목. 한 줄에 두 번 일치하면 두 번 나옵니다. `--limit`를 주지 않으면 100건에서 멈춥니다. |
| `tags` | 태그와 각각의 출현 횟수. |
| `tag <이름>` | 그 태그가 달린 파일. 앞의 `#`는 있어도 없어도 됩니다. |
| `tasks [--status open\|done\|cancelled\|all] [--file <경로>]` | 태스크. 기본값 `open`은 할 일과 진행 중입니다. |
| `backlinks <경로>` | 그 노트를 가리키는 링크. |
| `links <경로>` | 그 노트가 가진 링크와 각각이 어디로 가는지. |

`--vault`와 `--json`은 모든 명령에 쓸 수 있습니다.

## 경로와 줄 번호

넘기는 경로는 현재 디렉터리가 아니라 **볼트 루트** 기준이고 `/`를 씁니다. 명령이 출력하는 경로도 같은 방식이라, 한 명령의 출력을 다음 명령의 인자로 그대로 쓸 수 있습니다. 절대 경로는 볼트 안이면 받습니다. 볼트 밖은 `PATH_OUTSIDE_VAULT`로 거부합니다.

`--folder`는 숨김 폴더와 `node_modules`, `.git`, `.obsidian`, `.baram`을 받지 않습니다. 앱이 볼트를 읽을 때 건너뛰는 폴더이고, 명령은 앱이 보는 것을 알려 줍니다.

줄 번호는 1부터 셉니다.

## 출력

`--json`이 없으면 항목 하나가 한 줄이고 필드는 탭으로 나뉩니다. 필드 안의 탭, 줄바꿈, 캐리지 리턴, 백슬래시는 `\t`, `\n`, `\r`, `\\`로 씁니다. `read`만 예외로, 파일 내용을 그대로 출력합니다.

`--json`을 주면 모든 명령이 객체 하나를 출력합니다.

```json
{
  "vault": { "name": "Notes", "path": "/Users/me/Notes" },
  "truncated": false,
  "items": [{ "path": "docs/guide.md", "line": 12, "snippet": "…" }]
}
```

`truncated`는 `search`가 상한에서 멈췄을 때 `true`입니다. 값이 없는 필드는 빠지지 않고 `null`로 나옵니다. `vault`가 `null`인 경우는 볼트 밖에서 실행한 `vaults`뿐입니다.

## 오류와 종료 코드

| 종료 코드 | 뜻 |
| --- | --- |
| `0` | 성공했습니다. 결과가 비어 있어도 `0`입니다. |
| `1` | 명령을 끝내지 못했습니다. |
| `2` | 명령을 잘못 썼습니다. |

결과는 표준 출력으로, 오류와 경고는 표준 오류로 나갑니다. `--json`이면 명령이 알리는 오류도 객체입니다.

```json
{ "error": { "code": "FILE_NOT_FOUND", "message": "no file at notes/a.md", "candidates": [] } }
```

`message`의 문구가 아니라 `code`로 분기하십시오. `VAULT_NOT_FOUND`, `VAULT_AMBIGUOUS`, `PATH_OUTSIDE_VAULT`, `FILE_NOT_FOUND`, `INVALID_ARGUMENT`, `IO`가 있습니다.

표준 오류에는 이 객체가 아닌 것이 두 가지 더 나올 수 있습니다. 인자 해석기가 읽지 못하는 명령줄(없는 명령이나 플래그, 빠진 인자, 범위를 벗어난 값)은 `--json`을 읽기 전에 거절되므로 그 메시지는 일반 텍스트입니다(종료 코드 `2`). 그리고 경고는 따로 한 줄, `{"warning":{"message":"…"}}`로 다른 것보다 먼저 나옵니다. 앱 설정을 읽지 못했을 때가 그렇습니다.

## 앱과 다른 점

- **저장하지 않은 편집은 보이지 않습니다.** 명령은 디스크의 파일을 읽습니다.
- **`backlinks`는 노트 이름으로 찾습니다.** `[[notes/plan]]`처럼 폴더를 붙여 쓴 링크는 세지 않고, 한 줄에 같은 노트로 가는 링크가 둘이면 한 번만 알려 줍니다. 백링크 패널과 같습니다.
- **`links`는 클릭이 아니라 그래프가 푸는 방식으로 풉니다.** `[[./plan]]` 같은 상대 링크와 저널 날짜는 따라가지 않습니다. 다른 볼트로 가는 링크는 그 볼트의 별칭만 알려 주고 풀지 않습니다. 이 명령은 이번 실행이 고른 볼트의 색인을 읽습니다. 등록된 폴더가 볼트 안에 있으면 앱의 그래프는 그 폴더 자신의 색인을 쓰므로, 같은 이름의 노트가 둘일 때 결과가 다를 수 있습니다.
- **`tasks`는 볼트 하나를 읽습니다.** 태스크 패널은 범위 설정에 따라 여러 볼트를 보일 수 있습니다. 앱 설정에서 태스크에서 제외한 폴더는 여기서도 제외됩니다.
- **`search`는 `.md` 파일만 읽습니다.** 다른 명령은 `.markdown`도 읽습니다.
- **`backlinks`와 `links`는 부를 때마다 볼트의 링크를 색인합니다.** 최근 Mac에서 노트 10,000개에 0.5초쯤 걸립니다.

## AI 에이전트에게 알려 주기

명령이 어디 있는지와 읽기 전용이라는 점을 에이전트에게 알려 주십시오. 예를 들어 프로젝트의 `CLAUDE.md`에 이렇게 적습니다.

```markdown
My notes are a Baram vault at ~/Notes. Query it with the `baram` CLI (read-only):

- `baram --vault ~/Notes --json search "<text>"` — find notes
- `baram --vault ~/Notes read <path>` — read one
- `baram --vault ~/Notes --json backlinks <path>` — what links to it
- `baram --vault ~/Notes --json tasks` — open tasks

Paths are relative to the vault root. Exit code 0 with no items means "nothing found".
```
