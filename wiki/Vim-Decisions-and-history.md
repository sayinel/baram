# Vim Decisions and history

이 페이지는 **왜 이렇게 되어 있는가** 에 답한다. 무엇이 되는지는
[Overview](Vim-Overview), 어떻게 도는지는 [Architecture](Vim-Architecture) 가 답한다.

여기 적힌 결정은 append-only 다 — 뒤집히면 지우지 말고 뒤집힌 이유와 함께 남긴다. 결정을
되짚는 사람이 알아야 하는 것은 현재 상태가 아니라 **무엇을 저울질했는가** 이기 때문이다.

## 결정

| 결정                                                                          | 근거                                                                                                                                                                  |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| normal 모드의 클릭은 **탐색이지 편집 진입이 아니다**                          | vim 멘탈 모델 — 아웃라인은 탐색, 편집창은 입력, Esc 는 밖. [#408](https://github.com/sayinel/baram/issues/408) 에서 확정                                              |
| **visual block (`Ctrl-v`) 을 만들지 않는다**                                  | 리치 텍스트 트리에 "열" 개념이 성립하지 않는다. 평문 버퍼에서만 의미가 있는 기능                                                                                      |
| register 는 앱 전역이고 **문서에 저장되지 않는다**                            | vim buffer 의미론과 클립보드 등가. 플러그인에 노출하지 않는다                                                                                                         |
| 마우스 선택은 vim 명령 뒤에도 **유지한다**                                    | 사용자가 의도적으로 만든 복사 어포던스를 명령이 지우면 안 된다                                                                                                        |
| undo 스택은 **ProseMirror 하나** (코드블록 CM 에 자체 history 를 두지 않는다) | 블록 안과 밖이 한 스택이어야 `u` 가 예측 가능하다                                                                                                                     |
| `/` 검색은 **JS regex + 자체 라인 입력**                                      | vim 에뮬레이터의 관행이고, 앱의 `Cmd+F` 와 독립이어야 한다                                                                                                            |
| 거부 메시지는 **영어**                                                        | vim 관례. i18n 은 [#372](https://github.com/sayinel/baram/issues/372)                                                                                                 |
| normal 모드의 `Space` 는 **task 토글** (본가 vim 의 "오른쪽 이동" 이 아니다)  | WYSIWYG 에서 오른쪽 이동은 `l` 로 충분하고, 체크 토글이 실제로 유용하다. count 는 드롭하고(`/` 와 같다), task 가 아닌 줄에서는 침묵하며, 가장 안쪽 taskItem 을 잡는다 |

## 역사

### 한 번에 착지했다, 그리고 경계가 남았다

`#307` 이 **세 편집 표면을 한 PR 로** 착지시켰다 (2026-08-24). 모드·모션·오퍼레이터·visual·
find·register 가 source mode 와 WYSIWYG 와 코드블록에서 동시에 켜졌다.

그 뒤 한 달은 **경계** 의 시간이었다. 어려운 부분이 모달 엔진이 아니었다는 뜻이다 — 엔진은
한 번에 섰고, 그것이 다른 편집기와 만나는 자리가 남았다.

### 경계 작업의 순서

전체 목록이 아니라 **모양이 바뀐 지점들**이다. 빠짐없는 이력은 커밋 히스토리와
[#298](https://github.com/sayinel/baram/issues/298) 에 있다.

| 날짜  | PR     | 무엇이 드러났나                                                                                      |
| ----- | ------ | ---------------------------------------------------------------------------------------------------- |
| 08-24 | `#465` | 커서 selection 이 inline 내용 밖으로 나갈 수 있었다 — 착지 당일의 후속                               |
| 08-25 | `#469` | 코드블록 진입이 방향에 따라 달랐다. 같은 PR 에서 `Space` task 토글이 리뷰 건의로 들어왔다            |
| 08-25 | `#470` | island 마커 상수를 의존성 없는 leaf 로 — sanitizer 가 vim 기능 모듈을 역참조하던 계층 역전 해소      |
| 08-27 | `#483` | 블록 안팎을 오갈 때 **모드가 커서를 따라가지 않았다**                                                |
| 08-28 | `#490` | 코드블록 통합 코드 분리, `:N` 줄 이동                                                                |
| 08-28 | `#491` | 대형 파일 분리 캠페인 — 플러그인 본체를 상태·island 동기화·selection 커맨드로                        |
| 09-03 | `#532` | chrome 속성 커밋을 **단일 권한 관문**으로 — 미guard 호출자들이 read-only 에서도 속성을 바꾸고 있었다 |

읽는 방법: 앞의 넷은 "어디서 무엇이 키를 갖는가", 뒤의 셋은 "그 답을 어디에 두는가" 다.
전자가 UX 결정이고 후자가 구조 결정이다.

### 되풀이된 모양

이 목록에서 같은 모양이 세 번 나온다 — **경계에서 상태가 새거나 멈춘다.** 모드가 따라가지
않고(`#483`), 포커스가 어느 쪽 것인지 모호하고(`#469`), 권한이 없는 곳에서 속성이
바뀐다(`#532`). 매번 처치는 같았다: **그 경계를 누가 소유하는지 한 곳에서 정하고, 나머지는
거기에 묻게 한다.**

가장 값비쌌던 것은 이 목록에 없다 —
[WebKit selection churn](Vim-WebKit-selection-churn) 이다. 증상이 엉뚱한 곳을 가리켜
그럴듯한 시도 셋이 먼저 무너졌고, 그 기록이 따로 한 페이지를 차지한다.

## 아직 결정되지 않은 것

구현 현황과 남은 티어는 [#372](https://github.com/sayinel/baram/issues/372) 가 답한다.
설계 판단이 필요한 것 중 여기 적을 만한 것:

- 마우스 선택을 유지한다는 결정은 섰지만, 그 선택 위에서 `Cmd+C` 가 무엇을 복사해야 하는지는
  아직 답이 없다.
- 거부 메시지 i18n 은 결정이 아니라 범위 문제로 남아 있다 ([#372](https://github.com/sayinel/baram/issues/372)).
