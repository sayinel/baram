# CLI Overview

**앱 실행 파일 하나가 인자를 보고 편집기와 명령줄 도구 둘로 돈다.** 명령줄 도구는 AI 에이전트와
스크립트가 vault 를 조회하는 길이고, 읽기만 한다. 앱을 거치지 않고 앱과 같은 Rust 함수로 디스크의
vault 를 직접 읽는다. 이 페이지는 그 모양과 그 모양을 지키는 불변식을 다룬다 — 왜 그렇게 정했는지는
[Decisions and history](CLI-Decisions-and-history) 가 답한다.

| 층         | 하는 일                                                                                                     |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| 모드 분기  | argv 만 보고 GUI 와 CLI 를 가른다 (`cli::mode_for`)                                                         |
| vault 해석 | `--vault` 의 경로 · 이름, 또는 현재 디렉터리로 vault 하나를 고른다. 못 찾으면 실패한다                      |
| 경로 인자  | 노트 · 폴더 경로를 그 vault 안의 경로로 바꾸고, 앱이 보지 않는 자리를 거른다                                |
| 명령       | 조회 결과를 봉투에 담아 돌려준다. 직접 출력하지 않는다                                                      |
| 출력       | 탭 구분 텍스트(`read` 는 파일 내용 그대로), 또는 한 줄짜리 JSON 봉투. 실패는 오류 코드와 종료 코드로 알린다 |

## 두 모드, 실행 파일 하나

`main()` 이 Tauri 를 시작하기 **전에** argv 로 모드를 정한다. CLI 면 Tauri 를 시작하지 않고 tokio
런타임을 직접 만들어 명령 하나를 돌린 뒤 종료 코드로 끝난다. 앱이 떠 있어도 CLI 는 별도 프로세스이고,
둘은 통신하지 않는다.

판정은 **GUI 로 보낼 argv 를 열거하고 나머지를 전부 CLI 로 보낸다.** GUI 쪽은 인자가 없을 때와, 첫
인자가 macOS 가 앱 번들을 띄우며 붙이는 `-psn_` · `-NS` · `-Apple` 로 시작하거나, 절대 경로이거나,
`scheme://` 꼴의 URL 일 때다 — 둘째 인자부터는 보지 않는다.

- **거꾸로(아는 하위 명령만 CLI 로) 하지 않는다.** 그러면 `baram --json search x` 와 오타가 창을
  띄운다. 에이전트의 셸은 그 창이 끝날 때까지 멈추고, single-instance 가 없어 두 번째 앱이 뜬다.
- **절대 경로는 존재를 묻지 않는다.** 지워진 파일, 끊긴 드라이브, 권한 없는 파일에서 존재 검사는
  거짓이 되고, 업데이트 재시작은 원래 argv 를 다시 넘긴다. 그런 실행이 CLI 사용법 오류로 떨어지면
  Windows 의 GUI 서브시스템 실행 파일은 창도 메시지도 없이 끝난다.
- ‼️ **`-` 플래그로 앱을 다시 띄우는 플러그인**(자동 시작 · single-instance)을 더하면 그 플래그를
  GUI 쪽 목록에 넣어야 한다. 넣지 않으면 그 실행이 사용법 오류로 끝난다. 시험은 이것을 막아 주지
  않는다 — 경고는 `mode_for` 의 주석에 있다.

## 앱의 함수를, 앱 없이

vault 를 조회하는 로직은 원래 Tauri 타입이 없는 Rust 함수였다 — 파일 목록 · 읽기 · 검색 · 태그 ·
태스크 · 링크 인덱스. vault 를 읽는 명령은 이 함수들을 그대로 부른다. 앱과 같은 답을 내는 것이 목표이기 때문이다.
`links` 를 위해 링크 인덱스에 접근자 하나(`outgoing_resolved`)를 더했고, 그 안의 해석은 그래프 뷰의
해석기다. 그 결과로 따라오는 성질은 이렇다.

- **디스크를 읽는다.** 저장하지 않은 편집은 보이지 않는다.
- **링크 인덱스를 부를 때마다 짓는다.** 앱은 인덱스를 메모리에 쥐고 갱신하지만, CLI 프로세스는 명령
  하나로 끝난다. 그 비용은 재어 받아들였다 — 측정값과 조건은 사용자 문서에 있다.
- **앱의 등록 목록과 설정은 앱 데이터 폴더의 `config.json` 에서 읽는다.** 그 키들의 값을 만드는 쪽은
  Rust 가 아니라 프런트엔드의 zustand persist 다 — Rust 의 `set_config` 는 받은 문자열을 그 키에 그대로
  둔다. 스토어 형식이 바뀌면 CLI 가 빈 목록을 읽게 되므로 형식을 계약 시험으로 묶었다 — 프런트 시험이 실제 persist 출력에 CLI 가 읽는 경로와 타입이 있는지
  보고, Rust 시험이 같은 픽스처에서 뽑은 값을 단언하고, Rust 가 직렬화한 컨텍스트를 CLI 리더가
  되읽는다.

## 불변식

| 불변식                                                                                                                                                                                                                                 | 왜 · 무엇이 지키나                                                                                                                                                                                                                                                                                                                                                |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **읽기 전용** — vault, 앱의 `config.json`, 앱 로그 파일에 쓰지 않는다                                                                                                                                                                  | 종단 시험이 시험의 명령 목록을 텍스트와 `--json` 으로 모두 돌린 전후로 vault · `HOME` · `XDG_DATA_HOME` 의 스냅샷을 비교하고, 짝으로 시험이 직접 한 쓰기를 그 스냅샷이 잡는지도 본다. 그 명령 목록은 다른 시험이 `--help` 에 보이는 명령과 같음을 단언한다 — 보이는 명령을 더하면 거기서 깨지고, 숨긴 명령(`hide = true`)은 `--help` 에 나오지 않아 잡히지 않는다 |
| **조용한 대체가 없다** — vault 를 못 찾으면 `VAULT_NOT_FOUND` 로 끝나고, 앱에서 마지막으로 연 vault 로 대신하지 않는다                                                                                                                 | 대체하면 코드 저장소에서 부른 에이전트가 엉뚱한 vault 를 읽고도 모른다                                                                                                                                                                                                                                                                                            |
| **루트 표기는 하나다** — 한 실행의 vault 루트는 정규화한 절대 경로 하나이고, 인덱스 build · 조회 · 태스크 제외 판정 · 출력 상대화가 모두 그 표기를 쓴다                                                                                | 링크 인덱스는 노트의 나가는 링크를 build 가 받은 경로 문자열 그대로의 키 아래 담고, 태스크 제외 판정은 접두사 제거가 실패하면 조용히 제외하지 않는다 — 표기가 갈리면 오류 없이 답이 틀린다                                                                                                                                                                        |
| **상대 경로는 vault 루트 기준이고, 출력은 `/` 로 쓴다** — 노트 · 폴더 경로 인자의 상대 경로와, 결과 행이 vault 안의 파일을 가리키는 경로. 인자로는 vault 안의 절대 경로도 받는다                                                       | 한 명령의 출력을 다음 명령의 인자로 그대로 넣을 수 있다. vault 자신의 경로(봉투의 `vault.path`, `vaults` 의 행)는 절대 경로다                                                                                                                                                                                                                                     |
| **걷기가 가지 않는 자리를 받지 않는 인자가 있다** — `--folder` 는 앱의 vault 걷기가 건너뛰는 폴더를, `tasks --file` · `links` 는 걷기가 목록에 올리지 않는 파일(마크다운이 아닌 파일 · 숨김 파일 · 건너뛰는 폴더 안의 파일)을 거절한다 | 그 답은 앱이 보여 주지 않는 것을 보여 주게 된다. 이 규칙이 걸리지 않는 명령도 있다 — `read` 는 vault 안의 파일이면 받고, `backlinks` 는 아직 없는 노트와 첨부를 받으며, `search` 는 앱의 검색 함수를 그대로 써서 일반 폴더 안의 숨김 파일도 읽는다                                                                                                                |
| **경로 인자는 없음과 닿지 못함을 가른다** — `read` · `links` · `tasks --file` · `--folder` 에서 없는 것은 `FILE_NOT_FOUND`, 있는데 닿지 못한 것은 `IO` 와 OS 의 사유다                                                                 | 권한 없는 파일을 "없다" 고 하면 사용자는 파일이 지워졌다고 믿는다. 경로 인자의 판정은 `paths::file_arg` · `paths::folder_arg` 에 모여 있다                                                                                                                                                                                                                        |
| **JSON 은 공개 계약이다** — IPC 구조체를 그대로 직렬화하지 않고 CLI 전용 구조체로 옮겨 담는다                                                                                                                                          | IPC 구조체는 프런트엔드의 필요로 바뀐다. 옮겨 담는 자리에서 정렬 · 1 기준 줄 번호 · 경로 표기를 맞춘다. 종단 시험이 같은 명령 목록마다 봉투 전체를 기대 JSON 과 비교한다 — 키가 빠지거나 더해지면 실패한다                                                                                                                                                        |
| **분기는 `code` 로 한다** — 메시지의 문구는 계약이 아니다                                                                                                                                                                              | 오류 코드를 가르는 `match` 에는 `_` 갈래가 없어, 새 코드는 이름을 얻기 전에 컴파일되지 않는다                                                                                                                                                                                                                                                                     |
| **명령 함수는 쓰지 않는다** — 봉투를 돌려줄 뿐, stdout 에 쓰는 것은 `cli` 모듈의 진입부(`run` · `execute`)다                                                                                                                           | 같은 함수가 다른 앞단(MCP 서버 같은)의 뒤에 설 수 있다                                                                                                                                                                                                                                                                                                            |

## 앱과 같은 답, 일부러 다른 답

목표는 앱과 같은 답이고, 다른 곳은 이유를 적어 둔다. 갈림의 목록과 예는 사용자 문서의 "앱과 다른 점"
이 canonical 이다 — 여기는 갈림의 **종류**만 적는다. 이 wiki 는 위키링크를 이중 대괄호 없이
적는다(`alias::x`).

- **같은 함수, 같은 규칙.** `backlinks` 는 백링크 패널과 같은 인덱스 조회를 부르고, 노트가 자기 vault
  이름(별칭 · 공간 이름) 뒤에서도 읽히는 규칙을 앱과 같은 순수 함수 `own_aliases` 로 판정한다. CLI 는
  `config.json` 의 컨텍스트를 앱이 등록할 때 거치는 조건으로 걸러 그 함수에 넣는다 — 앱이 등록하지
  않을 vault 가 이름을 나눠 가지면 CLI 만 덜 세기 때문이다.
- **같은 함수, 다른 범위.** `tasks` 는 vault 하나를 읽고, 태스크 패널은 범위 설정을 따른다.
  `backlinks` · `links` 는 이번 실행이 고른 vault 의 인덱스 하나를 읽는다 — 등록이 겹치면 앱은 다른
  인덱스를 쓰거나 여러 인덱스의 답을 합친다.
- **일부러 다른 것.** `links` 는 그래프 뷰의 해석기를 쓰되, 다른 vault 로 가는 위키링크(`alias::x` 꼴)는
  해석하지 않고 별칭만 알린다. 그 링크를 이 vault 의 `x.md` 로 풀면 별칭이 가리키는 vault 의 노트가
  아닌 것을 답하게 된다. 그래프 뷰는 그 링크를 같은 이름의 로컬 노트로, 없으면 자리표시 노드로 긋는다.
- **두 링크 명령끼리.** `backlinks` 는 인덱스의 키(이름 · vault 루트 기준 경로 · 자기 이름 뒤)로 세고
  `links` 는 그래프의 해석기로 푼다. 그래서 상대 링크, 적힌 경로에 노트가 없는 경로 링크, 경로 없이
  쓴 첨부 이름, 자기 이름 링크 같은 곳에서 둘의 답이 갈린다.

## 두 번 밟지 말 것

1. **`Path::exists` · `is_file` · `is_dir` 은 메타데이터를 읽지 못하면 거짓이다.** 그 결과로 거르면
   권한 없는 파일이 `FILE_NOT_FOUND` 가 된다. v1 의 계획 코드에 이 결함이 세 번(`read` · `--folder` ·
   `tasks --file`) 있었다. `std::fs::metadata` 의 결과를 직접 가르는 판정이 `paths` 에 있으니, 새 경로
   인자는 그 판정을 지나게 할 것.
2. **`println!` 은 끊긴 파이프에서 panic 하고, 릴리스 프로필은 `panic = "abort"` 다.** 출력은 오류를
   돌려받는 쓰기로 하고, 받는 쪽이 먼저 닫은 파이프(`| head`)는 종료 `0` 으로 끝낸다. 이것을 시험하는
   출력은 파이프 버퍼보다 커야 한다 — 작으면 읽는 쪽이 닫기 전에 쓰기가 끝나 `println!` 구현도
   통과한다. 텍스트와 `--json` 은 다른 쓰기 길을 지나므로 둘 다 돌린다.
3. **내부 오류 타입의 `Display` 에는 한국어가 섞여 있다**(`FsError` · `ConfigError` · `IndexError`).
   그대로 내보내지 않고 코드별 영어 문구로 옮긴다.
4. **`read_dir` 순서는 시험이 고를 수 없다.** `files` 의 정렬 호출을 지워도 종단 시험이 초록이었다 —
   그 픽스처에서 APFS 의 `read_dir` 이 마침 정렬된 순서를 냈다. 정렬은 행을 만드는 순수 함수에 뒤집은
   입력을 먹이는 단위 시험으로 지킨다. 같은 줄 안의 링크 순서처럼 안정 정렬이 계약인 곳은 긴 입력으로
   시험한다 — 짧은 입력의 시험은 `sort_unstable_by_key` 로 바꿔도 통과했다.
5. **`search --folder` 를 기존 글로브 필터로 만들지 말 것.** 그 폴더 접두사는 문자열 접두사라 `docs`
   가 `docs-old/` 까지 먹고, 상한이 걷기 중에 먼저 차서 결과를 나중에 걸러도 늦다. 검색 루트 자체를
   그 폴더로 옮긴다.
6. **링크 해석은 메서드 하나로 연다 — 순서가 계약이다.** 다른 vault 링크를 먼저 가르지 않고 인덱스의
   맵에 물으면 위키링크 `journal::x` 가 로컬 `x.md` 로 풀린다. 조각을 따로 열면 호출자가 순서를 어길 수 있다.
