# CLI Links and app parity

CLI 의 답이 앱의 답과 어디서 같고 어디서 갈리는지, 그리고 링크 해석이 지키는 순서다. CLI 가 앱의
함수를 그대로 부르는 구조는 [Architecture](CLI-Architecture) 의 경계 2, 개요는
[Overview](CLI-Overview) 에 있다.

## 앱과 같은 답, 일부러 다른 답

목표는 앱과 같은 답이고, 다른 곳은 이유를 적어 둔다. 갈림의 목록과 예는
[사용자 문서](https://baram.ing/ko/docs/command-line/) 의 "앱과 다른 점" 이 canonical 이다 — 여기는
갈림의 **종류**만 적는다. 이 wiki 는 위키링크를 이중 대괄호 없이 적는다(`alias::x`).

- **같은 함수, 같은 규칙.** `backlinks` 는 백링크 패널과 같은 인덱스 조회를 부르고, 노트가 자기 vault
  이름(별칭 · 공간 이름) 뒤에서도 읽히는 규칙을 앱과 같은 순수 함수 `own_aliases` 로 판정한다. CLI 는
  `config.json` 의 컨텍스트를 앱이 등록할 때 거치는 조건으로 걸러 그 함수에 넣는다 — 앱이 등록하지
  않을 vault 가 이름을 나눠 가지면 CLI 만 덜 세기 때문이다.
- **같은 함수, 다른 범위.** `tasks` 는 vault 하나를 읽고, 태스크 패널은 범위 설정을 따른다.
  `backlinks` · `links` 는 이번 실행이 고른 vault 의 인덱스 하나를 읽는다 — 등록이 겹치면 앱은 다른
  인덱스를 쓰거나 여러 인덱스의 답을 합친다.
- **일부러 다른 것.** `links` 는 그래프 뷰의 해석기를 쓰되, 다른 vault 로 가는 위키링크(`alias::x` 꼴)는
  해석하지 않고 별칭만 알린다. 그 링크를 이 vault 의 `x.md` 로 풀면 별칭이 가리키는 vault 의 노트가
  아닌 것을 답하게 된다. 그래프 뷰는 그 링크를 같은 이름의 로컬 노트로, 없으면 자리표시 노드로 긋는다.
- **두 링크 명령끼리.** `backlinks` 는 인덱스의 키(이름 · vault 루트 기준 경로 · 자기 이름 뒤)로 세고
  `links` 는 그래프의 해석기로 푼다. 그래서 상대 링크, 적힌 경로에 노트가 없는 경로 링크, 경로 없이
  쓴 첨부 이름, 자기 이름 링크 같은 곳에서 둘의 답이 갈린다.

## 한 수정이 앱과 CLI 에 함께 닿은 이유

수동 확인 중 CLI 로 찾은 결함이 있었다 — 이름이 분해형(NFD)으로 저장된 노트가 완성형(NFC)으로 쓴
위키링크의 대상이 되지 못했다. NFD 결함의 Rust 쪽 수정(`#816`)이 한 자리에서 백링크 패널 · 그래프와
CLI 에 함께 닿은 것은 구조의 결과다 — CLI 가 앱의 링크 인덱스를 그대로 쓰기 때문이다. 그 PR 은 앱
화면을 눌러 보지 않고 같은 인덱스를 CLI 로 확인했다.

에디터 쪽(링크 클릭 · 위키링크 자동완성 메뉴 · 빠른 열기 등)에는 `#816` 이 링크 인덱스에 건 이름
접기(NFC → 소문자 → NFC)와 같은 접기를 TypeScript 에서 따로 걸었다(`#832`). 전말은 [Decisions and history](CLI-Decisions-and-history) 의 역사에 있다.

## 두 번 밟지 말 것

**링크 해석은 메서드 하나로 연다 — 순서가 계약이다.** 다른 vault 링크를 먼저 가르지 않고 인덱스의
맵에 물으면 위키링크 `journal::x` 가 로컬 `x.md` 로 풀린다. 조각을 따로 열면 호출자가 순서를 어길 수
있다.
