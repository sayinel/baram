# Vim Overview

**설정 토글 하나로 세 편집 표면에 동시에 켜지는 vim 모달 편집.** 사용자에게는 한 기능이지만
구현은 엔진 둘이다 — 어디서 기성품을 쓰고 어디서 직접 만들었는지, 그리고 왜 그 선이 거기인지가
이 페이지의 내용이다.

| 표면                     | 엔진                            | 왜                                       |
| ------------------------ | ------------------------------- | ---------------------------------------- |
| Source mode (CodeMirror) | `@replit/codemirror-vim` 어댑터 | 검증된 전체 기능 — 직접 만들 이유가 없다 |
| WYSIWYG (ProseMirror)    | **자체 엔진**                   | 리치 텍스트 위의 vim 은 기성품이 없다    |
| 코드블록 (블록별 CM)     | 같은 어댑터 (모듈 캐시 공유)    | source mode 와 동일 + 경계 배선          |

## 왜 WYSIWYG 만 자체 엔진인가

vim 의 모델은 **줄과 칼럼으로 된 평문 버퍼를 전제한다.** source mode 와 코드블록은 실제로
그것이다. 거기서 검증된 어댑터를 쓰지 않을 이유가 없다 — 직접 만들면 기능의 긴 꼬리를 처음부터
다시 만드는 일이고, 그렇게 얻는 것이 없다.

ProseMirror 문서는 트리다. 원자 노드(수식·mermaid·이미지·hr)가 있고 테이블이 있고, **"한 줄"
이라는 것이 문서에 존재하지 않는다.** `dd` 가 무엇을 지우는지 답하려면 먼저 줄을 **정의해야
한다** — 수식 블록 하나는 한 줄인가, hardBreak 로 나뉜 문단은 몇 줄인가, 테이블 행 하나는
어떤가. 그 정의가 [Architecture](Vim-Architecture) 의 행 모델이고, 기성품 어댑터가 대신 내려
줄 수 있는 결정이 아니다.

그 위에 브라우저 층의 문제가 얹힌다. 모달 상태의 뷰는 non-editable 이어야 하고(아래 IME 항목),
그러면 PM 의 selection 동기화가 멈춘다 —
[WebKit selection churn](Vim-WebKit-selection-churn) 이 그 수사 기록이다. 리치 텍스트 위의
vim 이 기성품으로 없는 이유는 키 바인딩이 아니라 이런 층에 있다.

코드블록은 source mode 와 **같은 어댑터를 모듈 캐시로 공유한다.** 세 표면에 세 구현을 두지 않는
방법이고, 블록별로 더해지는 것은 경계 UX(블록 안으로 들어가고 나오는 규칙)와 그 경계를
성립시키는 배선이다 — 모듈이 로드되기 전에 세우는 동기 editing-host 장벽, PM↔CM 핸드오프,
섬 상태 피드.

## 한국어는 1급 시민이다

세 항목 모두 **정공법이고, 나중에 덧붙일 수 없는 층에 박혀 있다.**

- **IME 차단은 선언적이다.** normal/visual 에서 **editing host 자체를 제거한다** — WebKit 이
  조합할 곳이 없으니 자모가 문서에 새지 않는다. **선언적 제거가 1차 방어이고**, 그 아래 입력
  취소 가드가 한 겹 더 깔린다(`beforeinput` 취소 · `handleTextInput`) — 실기기 프로브가 정한
  순서다. 세 표면이 같은 원리를 공유한다. 대신 non-editable 이라는 대가를 치른다.
- **모든 명령이 한글 입력 소스에서 동작한다.** 한글이 켜진 채 `j` 를 누르면 `event.key` 는
  `ㅓ` 지만, 키 정규화 층이 물리키로 명령을 읽고 원래 문자는 따로 실어 보낸다. 그 규칙이 한
  곳에만 있으므로 새 명령을 추가할 때 다시 고민하지 않는다.
- **`f` + `ㄱ` 은 초성 검색이다.** find 타겟은 리터럴 문자로 받아야 하고, 한글 타겟은 한글을
  찾는다.

이 셋이 각각 뷰의 editable 판정, core 의 키 어휘, core 의 문자 매칭에 들어가 있다. 사후에
끼우면 경로마다 동작이 갈린다 — 1급 시민이라는 말의 실질적 의미가 그것이다.

## 읽는 순서

1. **[Architecture](Vim-Architecture)** — 먼저 읽는다. 층과 경계, 그리고 경계가 왜 거기인지.
   나머지 페이지는 이 그림 위의 이야기다.
2. 그 다음은 관심 영역으로. selection 이 되돌려지는 증상을 만났다면
   **[WebKit selection churn](Vim-WebKit-selection-churn)** 으로 직행할 것 — 증상이 엉뚱한
   곳을 가리키는 버그라서, 모르고 파면 같은 반증을 다시 밟는다.
3. **[Code map](Vim-Code-map)** — 파일 위치. 경로는 그 페이지에만 산다.

## 어디까지 와 있나

**척추는 세 표면 모두 구현돼 있다** — 모드(normal · insert · visual) · 모션 · 오퍼레이터
(d/c/y) · find(`f`/`t`) · register · `/` 검색. 남은 것은 #372 에 티어 1~4 로 산다: 티어 1 이
`.` 반복 · 텍스트 오브젝트 · `r` · curswant 이고, 티어 4 가 매크로 · 마크 · named register 다.

**이 골격은 변하지 않는다** — 어느 티어의 무엇이 착지했는지만 이슈에서 움직이므로, 정확한
현황은 여기가 아니라 #372 를 볼 것.
