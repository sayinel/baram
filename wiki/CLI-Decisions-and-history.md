# CLI Decisions and history

이 페이지는 **왜 이렇게 되어 있는가** 에 답한다. 무엇이 어떻게 도는지는 [Architecture](CLI-Architecture),
쓰는 법은 [사용자 문서](https://baram.ing/ko/docs/command-line/) 가 답한다.

여기 적힌 결정은 append-only 다 — 뒤집히면 지우지 말고 뒤집힌 이유와 함께 남긴다. 결정을 되짚는
사람이 알아야 하는 것은 현재 상태가 아니라 **무엇을 저울질했는가** 이기 때문이다.

## 결정

| 결정                                                                                                                         | 근거                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **앱을 거치지 않고 vault 를 직접 읽는다**                                                                                    | 읽기 전용에서 앱 경유가 주는 것은 앱이 메모리에 쥔 상태를 그대로 쓰는 것이다 — 링크 인덱스, 그리고 앱이 실제로 등록해 쥔 컨텍스트 목록 같은 것. CLI 는 인덱스를 부를 때마다 짓고, 컨텍스트 목록은 `config.json` 에서 다시 읽는다(그래서 `#813` 은 앱의 등록 조건을 따로 따라야 했다). 대가로 앱에 새 입구(소켓)가 생기고 그 입구의 인증 · 경로 제한을 따로 설계해야 한다 — Tauri ACL 은 창 라벨로 허용을 판정하므로 소켓 요청에는 걸리지 않는다. 앱이 꺼져 있으면 창도 띄워야 한다. 인덱스를 매번 짓는 비용은 재어 받아들였다. 기각: 앱 경유, 처음부터 "앱이 있으면 앱, 없으면 직접" 인 혼합형(명령마다 두 경로를 첫 단계에서 함께 시험해야 한다)                                                                                                        |
| **읽기 전용으로 자른다**                                                                                                     | 쓰기 명령은 열린 탭과 충돌하지 않으려면 앱을 거쳐야 한다 — 위 결정이 피한 새 입구를 요구한다. 읽기 가운데서도 판정 로직을 새로 만들어야 하는 vault 전체 `unresolved` · `orphans` 는 뺐다. 그래프용 해석은 해석하지 못한 대상에도 경로를 지어 노드로 넣으므로, vault 전체에 걸친 그 판정을 새로 만들어야 한다                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **앱 실행 파일 하나가 두 모드로 돈다**                                                                                       | 두 번째 실행 파일을 번들에 싣지 않으므로 서명 · 공증 · universal 빌드가 그대로이고, CLI 와 앱의 버전이 어긋날 수 없다. 기각: 별도 실행 파일(앱 라이브러리를 링크하면 크기가 늘고, 링크하지 않으려면 vault 모듈을 Tauri 없는 crate 로 떼어 내야 한다), `tauri-plugin-cli`(시작할 때 인자를 파싱할 뿐 실행 중인 인스턴스와 말하지 않는다), single-instance 로 인자 전달(두 번째 인스턴스는 알리고 끝나 결과를 돌려받을 채널이 없다)                                                                                                                                                                                                                                                                                                                        |
| **분기는 GUI 로 가는 argv 를 열거하고, 절대 경로는 존재를 묻지 않는다**                                                      | 아는 하위 명령만 CLI 로 받으면 앞에 전역 플래그를 둔 호출과 오타가 창을 띄운다. 존재하는 경로만 GUI 로 받으면 존재 검사가 거짓이 되는 파일 연결 실행과 업데이트 재시작이 조용히 끝난다. 이유의 전문은 [Architecture](CLI-Architecture) 의 "경계 1: 모드 분기" 절                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **vault 를 못 찾으면 실패한다 — 앱의 활성 vault 로 대체하지 않는다**                                                         | 조용한 대체는 코드 저장소에서 부른 에이전트가 엉뚱한 vault 를 읽고도 모르게 만든다. 기각: `.baram/` 폴더를 표식으로 찾기 — 한 기기에서 잰 등록 컨텍스트에 그 폴더가 없는 것이 있었다(2026-10-03)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **`--vault` 없이 현재 디렉터리로 고를 때 등록이 겹치면 vault 유형이 먼저, 그 안에서 가장 바깥이다**                          | 둘 다 앱과 맞춘 것이다. "가장 바깥" — 앱의 태스크 스캔은 다른 루트 아래의 루트를 빼고, 백링크는 파일을 담은 모든 컨텍스트의 인덱스를 합친다. "vault 유형 먼저" — 앱 태스크 패널의 기본 범위는 vault 유형 컨텍스트(와 태스크 홈)를 읽는다. 유형을 가리지 않으면 folder 컨텍스트 `~/Work` 안에 vault `~/Work/notes` 가 있을 때 `~/Work` 전체를 걷는다. 기각: 가장 안쪽, 유형을 가리지 않는 가장 바깥                                                                                                                                                                                                                                                                                                                                                       |
| **vault 를 고를 때 승인 저장소(§329–§336)와 대조하지 않는다**                                                                | CLI 는 이름을 경로로 풀 뿐 asset scope 같은 권한을 부여하지 않고, 결과로 읽는 파일은 사용자가 셸로도 읽을 수 있다. `config.json` 의 매핑을 바꿀 수 있는 웹뷰와 trusted 플러그인은 이미 전권이고(§259), sandboxed 플러그인은 그 쓰기에 닿지 못한다. 그래서 `PATH_OUTSIDE_VAULT` 도 보안 경계가 아니라 에이전트가 범위를 벗어나지 않게 하는 규칙이다. Obsidian · Logseq 인기 플러그인을 대조한 조사가 MCP 서버를 권하며 붙인 조건 — vault 경계 인가를 통과해야 한다 — 과 갈리는 결정이다. 그 조건은 앱이 서버가 되는 구조를 전제한 것으로 읽힌다(권고 본문에 명시는 없다). CLI 는 `#813` 부터 그 저장소를 읽지만, `backlinks` 가 앱이 등록하지 않을 컨텍스트를 자기 vault 이름 판정에서 빼는 데만 쓴다 — vault 를 고르거나 읽는 일을 막는 데는 쓰지 않는다 |
| **입력 경로는 현재 디렉터리가 아니라 vault 루트 기준이다**                                                                   | 한 명령이 출력한 경로를 다음 명령의 인자로 그대로 넣을 수 있다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **CLI 의 JSON 은 공개 계약이다 — CLI 전용 구조체로 옮겨 담는다**                                                             | IPC 구조체는 프런트엔드의 필요로 바뀐다. 옮겨 담는 자리가 정렬 · 1 기준 줄 번호 · 경로 표기를 맞추는 자리이기도 하다. 검색 결과의 열 위치는 뺐다 — 바이트 오프셋이라 한글 본문에서 글자 위치와 다르다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **CLI 가 만드는 문구는 영어이고, 호출자는 `code` 로 분기한다**                                                               | 내부 오류의 `Display` 에 한국어가 섞여 있어 그대로 내지 않고 코드별 영어 문구로 옮겼다. 메시지가 인용하는 경로 · 이름과 `IO` 의 OS 실패 설명은 그대로 싣는다. 메시지를 앱의 UI 언어로 내는 것은 v1 범위 밖으로 남겼다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **앱 로그 파일에 쓰지 않는다 — 진단은 `BARAM_LOG` 가 있을 때만 stderr 로**                                                   | 회전과 상한이 있는 앱 로그에 실행 중인 앱과 CLI 가 함께 쓰면 쓰는 쪽이 둘이 된다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **명령 함수는 봉투를 돌려줄 뿐 직접 출력하지 않는다**                                                                        | 같은 함수를 다른 앞단(MCP 서버)이 부를 수 있게 입출력을 serde 구조체로 둔다. 실제 단계와 순서는 [추적 이슈](https://github.com/sayinel/baram/issues/847) 가 답한다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **`links` 는 그래프 뷰의 해석기를 쓰되, 다른 vault 로 가는 링크는 별칭만 알린다**                                            | 에디터의 클릭 해석은 TypeScript 에 있고, 링크 인덱스의 해석기(`resolve_link`)를 쓰는 앱 화면은 그래프 뷰다 — 앱 없이 읽는 CLI 가 부를 수 있는 것은 그쪽이다. 다른 vault 링크를 푸는 Rust 커맨드 `resolve_cross_vault_link`(§87)는 앱의 컨텍스트 상태를 받아 앱 없이는 부를 수 없다. 다른 vault 링크를 이 vault 의 맵에 물으면 같은 이름의 로컬 노트로 풀려, 별칭이 가리키는 vault 의 노트가 아닌 것을 답한다. 순서를 지키도록 링크 인덱스는 이 해석을 메서드 하나로 연다                                                                                                                                                                                                                                                                                 |
| **`backlinks` 는 아직 없는 노트를 받고, 폴더는 받지 않는다**                                                                 | 아직 없는 노트를 가리키는 링크를 찾는 것은 정당한 질의다. 폴더를 받으면 그 이름의 노트를 묻는 셈이 되어, 폴더 이름과 같은 링크가 답으로 나왔다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **`backlinks` 는 노트의 자기 vault 이름 규칙을 앱과 한 함수로 판정한다 ([#813](https://github.com/sayinel/baram/pull/813))** | 같은 판정이 두 벌이면 어긋난다. 앱의 판정을 순수 함수로 꺼내 앱과 CLI 가 함께 부른다. CLI 는 `config.json` 의 컨텍스트를 앱이 등록할 때 거치는 조건(승인 · 형식 · 경로의 꼴 · vault 설정 · 같은 경로의 첫 등록)으로 거른다 — 그대로 쓰면 앱이 등록하지 않을 vault 가 이름을 나눠 가져 CLI 만 덜 센다. 그 조건 가운데 경로의 꼴과 같은 경로의 첫 등록은 `ContextManager::add` 의 조건을 옮겨 적은 것이라, 그 조건들은 앱과 CLI 에 따로 있다. 기각: 판정을 CLI 에 복사하기, `config.json` 의 목록을 그대로 쓰고 다른 점을 문서에 적기                                                                                                                                                                                                                      |
| **설치는 문서 안내만 한다 — macOS 의 `PATH` 에는 심볼릭 링크가 아니라 셸 함수나 래퍼 스크립트**                              | 에이전트는 절대 경로로 부르면 된다. 앱이 `/usr/local/bin` 에 링크를 만들면 앱에 관리자 권한 요청이 생긴다. 심볼릭 링크 경로로 인자 없이 앱을 띄우면 tauri-utils 가 경로 조상의 심볼릭 링크를 거부하고, 그 뒤 업데이트 재시작이 앱을 다시 띄우지 않는다 — 그 검사는 macOS 에서만 컴파일된다                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Windows 는 코드가 공통이고, 대화형 콘솔 출력용 `baram.com` 중계 파일은 v1 에 넣지 않는다**                                 | 에이전트는 대개 출력을 파이프로 받는다. GUI 서브시스템 실행 파일이 파이프로 출력과 종료 코드를 넘기는지는 이 결정 때 재지 않았다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## 역사

### 조사가 권한 길과 다르게 갔다

설계에 앞선 조사는 Obsidian 1.12 의 CLI 를 대조했다. 그 CLI 는 앱이 떠 있어야 하고, 떠 있지 않으면
첫 명령이 앱을 띄운다([공식 문서](https://obsidian.md/help/cli)). 조사는 같은 **앱 경유**를 권했고,
근거는 넷이었다 — 쓰기 로직이 TypeScript 에 있다, 직접 쓰면 열린 탭과 충돌한다, 직접 읽으면 링크
인덱스를 매번 지어야 한다, 직접 읽으면 프런트엔드가 쓰는 `config.json` 형식에 묶인다.

v1 은 읽기 전용으로 범위를 자르며 이것을 뒤집었다. 앞의 둘은 쓰기 단계의 문제였다. 인덱스 비용은
조사 때 재지 않았던 것을 재어 받아들였다. 형식 결합은 계약 시험으로 묶었다. 쓰기는 앱을
거쳐야 한다는 판단은 그대로 남았다.

### 되풀이된 모양

같은 모양이 세 번 나온다 — **한 판정이 두 곳에 있으면 갈라진다.**

- 경로 인자의 "없음 대 닿지 못함" 판정을 `read` 와 `tasks --file` 이 따로 들고 있었다. 리뷰가 그것을
  `file_arg` 하나로 합치게 했다. 폴더 인자(`folder_arg`)의 같은 갈래와 두 벌인 것은 추적 이슈에 있다.
- 링크 해석의 순서. 조각을 따로 열면 호출자가 순서를 어겨 위키링크 `journal::x` 가 로컬 노트로 풀린다 —
  메서드 하나로 열었다.
- 노트의 자기 vault 이름 판정. 앱 안에만 있던 것을 순수 함수로 꺼내 앱과 CLI 가 함께 부른다(`#813`). 그
  판정에 넣을 컨텍스트를 거르는 등록 조건 가운데 경로의 꼴과 같은 경로의 첫 등록은 옮겨 적은 사본으로
  남았다(결정 표).

위의 판정마다 처치는 같았다: **판정을 한 곳에 두고 나머지가 그것을 부르게 한다.** 등록 조건의 그
사본은 그 처치 밖에 남았다. NFD 결함의 Rust 쪽 수정(`#816`)이 한 자리에서 백링크 패널 · 그래프와
CLI 에 함께 닿은 것도 같은 구조의 결과다 — CLI 가 앱의 링크 인덱스를 그대로 쓰기 때문이다.

## 아직 결정되지 않은 것

구현 현황과 다음 단계는 [추적 이슈](https://github.com/sayinel/baram/issues/847) 가 답한다. 설계
판단이 필요한 것 중 여기 적을 만한 것:

- **텍스트 모드의 잘림 표시.** `search` 가 상한에서 멈추면 JSON 봉투는 `truncated` 로 알리지만 텍스트
  출력에는 그 표시가 없다. stdout 의 행 형식을 지키면서 어디로 알릴지는 정해지지 않았다.
- **첨부 파일의 백링크 키.** 경로 없는 이름은 확장자를 뗀 이름으로 찾아, `papers/Paper.pdf` 를
  `Paper.pdf` 로 쓴 위키링크를 놓치고 `Paper` 로 쓴 위키링크를 센다. 확장자를 포함한 이름을 키로
  더할지, `Paper` 로 쓴 링크를 첨부에서 뺄지가 함께 걸린다 — 앱의 백링크 패널도 같은 함수를 부른다.
- **front matter 태그의 `#`.** front matter 의 `tags: ["#solo"]` 는 `#` 가 붙은 채 저장되고 `tag` 는
  인자의 앞 `#` 를 떼므로, CLI 로는 그 태그에 닿지 않는다. 저장 형태를 하나로 할지(앱의 태그 목록과
  rename 에도 걸린다), CLI 가 두 이름을 모두 물을지 정해야 한다.
